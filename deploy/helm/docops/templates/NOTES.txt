Before the pods can start, check:
  1. Secret "{{ include "docops.databaseSecretName" . }}" must exist in this namespace with the key {{ .Values.database.secretKey }} (a postgres:// URL).
     kubectl --namespace {{ .Release.Namespace }} create secret generic {{ include "docops.databaseSecretName" . }} --from-literal={{ .Values.database.secretKey }}='postgres://USER:PASSWORD@HOST:5432/docops?sslmode=require'
     The database needs the pgvector extension and the docops_app role: see deploy/README.md.
{{- if not .Values.secrets.existingSecret }}
  2. Secret "{{ include "docops.secretName" . }}" was generated by this chart (token and preview signing secrets, and the build-signing key).
     Use secrets.existingSecret when you render offline (GitOps) or want to manage the keys yourself.
{{- else }}
  2. Secret "{{ .Values.secrets.existingSecret }}" must exist and hold DOCOPS_TOKEN_SIGNING_SECRET, DOCOPS_PREVIEW_SECRET and DOCOPS_SIGNING_KEY_PEM.
     Every API replica must share them. Create the key with: openssl genpkey -algorithm ed25519
{{- end }}

  3. Bucket "{{ .Values.objectStorage.s3.bucket }}" must exist{{ with .Values.objectStorage.s3.endpoint }} at {{ . }}{{ end }}, and Secret "{{ default (include "docops.secretName" .) .Values.objectStorage.s3.credentials.existingSecret }}" must hold
     {{ .Values.objectStorage.s3.credentials.accessKeyIdKey }} and {{ .Values.objectStorage.s3.credentials.secretAccessKeyKey }}: an access key with s3:GetObject and s3:PutObject on the bucket's objects and s3:ListBucket on the bucket.
{{- else if not .Values.objectStorage.filesystem.existingClaim }}

WARNING: objectStorage.filesystem.existingClaim is empty, so uploaded builds and blobs live in an emptyDir and are lost when the
API pod restarts. Set it to a PersistentVolumeClaim (it must be ReadWriteMany to run more than one API replica), or keep the
blobs in an S3-compatible bucket (objectStorage.type=s3).
{{- else if and (eq .Values.api.strategy.type "RollingUpdate") (not .Values.api.autoscaling.enabled) (le (int .Values.api.replicaCount) 1) }}

NOTE: if the claim "{{ .Values.objectStorage.filesystem.existingClaim }}" is ReadWriteOnce, a rolling update cannot attach it to the new API pod while the old
one still holds it. Set api.strategy.type=Recreate and api.strategy.rollingUpdate=null.
{{- end }}
